# Quarto deployment guide

The paper is built from numerical outputs generated by the model. Build commands
must run from the repository root so the pipeline can write the paper includes,
variables, and figures before Quarto reads them.

## Local build

The verified rendering environment uses Python 3.13.9, uv 0.11.7, and Quarto
1.9.36. Python dependencies and their hashes are recorded in `uv.lock`. Install
Quarto separately; PDF rendering also requires a TeX installation (for example,
`quarto install tinytex`).

```bash
make install
make check-results
make paper
make pdf
```

`make paper`, `make pdf`, `make latex`, and `make serve` regenerate their model
inputs first. `make replicate` regenerates results and renders both HTML and PDF.
The default build uses illustrative exact welfare scenarios and does not install
PolicyEngine or calculate a national welfare total.

To inspect the pipeline directly:

```bash
uv run --no-sync python -m taxuncertainty.pipeline
uv run --no-sync python -m taxuncertainty.pipeline --check
```

The second command checks committed outputs against a fresh calculation. It is
also run in CI before outputs are regenerated, so a stale result cannot be hidden
by a successful paper render. See `REPRODUCING.md` for model and validation scope.

## Tests and optional validation

```bash
make test
make lint
```

Fast tests do not require PolicyEngine. Tests marked `policyengine` require an
explicit opt-in and the managed optional dependency, pinned to
`policyengine[us]==5.3.0`:

```bash
make test-policyengine
```

This target installs the optional dependency into `.venv`. Run `make install` to
restore the smaller default environment. A missing optional package produces an
explicit dependency error when validation is requested; it is never replaced by
a fake module in the test process.

## GitHub Actions

CI installs locked dependencies, checks formatting and fast tests, validates
committed model outputs, and tests an installed wheel from a temporary directory
outside the checkout. The wheel test checks that `results.json` and
`parameters.yaml` are readable package resources.

The paper job pins Quarto to 1.9.36, generates model inputs, and renders HTML and
PDF. GitHub Pages publishes `paper/_build/` on successful pushes to `main`, after
both tests and paper rendering pass. Same-repository pull requests can produce a
Netlify preview when the existing Netlify credentials are configured.

## Paper structure

- `paper/_quarto.yml` configures the Quarto project.
- `paper/index.qmd` is the article entrypoint.
- `paper/chapters/*.md` contain the manuscript.
- `paper/generated/` contains model-generated paper inputs.
- `paper/_variables.yml` supplies generated numerical values to Quarto.
- `paper/references.bib` supplies bibliography data for Pandoc citeproc.
- `paper/_build/index.html` and `paper/_build/index.pdf` are rendered outputs.
